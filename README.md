# Movie Reservation System

Проект представляет собой серверную часть сервиса онлайн-бронирования билетов в кинотеатр. Система позволяет пользователям просматривать фильмы, изучать расписание сеансов, проверять доступность мест и оформлять бронирование. Администратор может управлять каталогом фильмов, залами и сеансами, а также контролировать размещённые бронирования.

## Технологический стек

- Python 3.14
- FastAPI — основной веб-фреймворк для API
- SQLAlchemy 2.0 — ORM для работы с базой данных
- Alembic — миграции схемы базы данных
- PostgreSQL 15 — основная реляционная база данных
- Redis 7 — кэширование и ограничение частоты запросов
- JWT — аутентификация и обновление токенов доступа
- Pydantic v2 — валидация данных и схемы запросов
- Uvicorn — запуск приложения ASGI
- Docker Compose — локальный запуск PostgreSQL и Redis
- Pytest, httpx, aiosqlite — автоматизированное тестирование
- Python-Multipart, aiofiles — работа с файлами и загрузкой изображений

## Структура базы данных

В проекте используется реляционная схема данных с сущностями, связанными по ключам. Основные таблицы:

- `users` — пользователи системы
  - `id`
  - `nickname`
  - `email`
  - `password_hash`
  - `created_at`
  - `role`
  - `is_active`
  - `is_superuser`
- `movies` — фильмы в каталоге
  - `id`
  - `title`
  - `description`
  - `image`
  - `genre`
  - `director`
  - `length`
- `halls` — кинозалы
  - `id`
  - `hall_number`
- `shows` — сеансы
  - `id`
  - `movie_id`
  - `hall_id`
  - `start`
  - `finish`
- `chairs` — места в залах
  - `id`
  - `hall_id`
  - `chair_number`
- `reservations` — бронирования билетов
  - `id`
  - `show_id`
  - `user_id`
  - `chair_id`

### Ограничения и связи

- Один пользователь может иметь несколько бронирований.
- Одно место в рамках конкретного сеанса нельзя забронировать дважды.
- У каждого зала есть набор кресел с уникальным номером внутри зала.
- Сеансы привязаны к конкретному фильму и залу.
- При удалении фильма, сеанса или зала связанные данные удаляются каскадно.

## API

Проект предоставляет REST API для всех основных сценариев работы сервиса.

### Аутентификация

- `POST /auth/registration` — регистрация нового пользователя
- `POST /auth/login` — вход в систему
- `GET /auth/logout` — выход из системы
- `GET /auth/refresh` — обновление access token через refresh token

### Фильмы

- `GET /movies/` — получение списка всех фильмов
- `GET /movies/{id}` — получение фильма по идентификатору
- `POST /movies/` — создание фильма (только для администратора)
- `PATCH /movies/{id}` — обновление данных фильма
- `DELETE /movies/{id}` — удаление фильма
- `GET /movies/images/{image_path}` — получение изображения фильма

### Сеансы

- `POST /shows/` — добавление нового сеанса
- `GET /shows/` — получение сеанса по идентификатору
- `GET /shows/available/` — получение доступных сеансов по фильму и времени
- `GET /shows/hall/{hall_id}/` — получение списка мест в зале
- `DELETE /shows/` — удаление сеанса

### Бронирования

- `POST /reservation/` — создание бронирования
- `GET /reservation/` — список всех бронирований для администратора
- `GET /reservation/{show_id}` — бронь по идентификатору сеанса
- `GET /reservation/user/{user_id}` — бронирования конкретного пользователя
- `GET /reservation/admin/show/{show_id}` — бронирования сеанса для администратора
- `DELETE /reservation/{reservation_id}` — отмена бронирования

### Залы

- `GET /hall/` — получение списка доступных залов

### Безопасность и поведение

- Используются JWT-токены для доступа к защищённым маршрутам.
- Для администраторских операций применяется проверка роли пользователя.
- В проекте настроен CORS и middleware для ограничения частоты запросов.
- Для кеширования и контроля нагрузки используется Redis.

## Функционал

- Регистрация и вход пользователей
- JWT-аутентификация с refresh-токенами и cookie
- Просмотр каталога фильмов и их постеров
- Управление расписанием сеансов
- Проверка доступности мест в зале
- Создание, просмотр и отмена бронирований
- Разделение прав доступа: пользователь и администратор
- Защита от повторного бронирования одного и того же места на одном сеансе
- Кэширование результатов в Redis для уменьшения нагрузки на базу данных
- Загрузка изображений фильмов в локальное хранилище

## Запуск проекта

### Установка зависимостей

```bash
uv sync
```

### Запуск баз данных через Docker

```bash
docker compose up -d
```

### Запуск сервера

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### Пример файла окружения

```bash
POSTGRES_DB=movie_reservation
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5433/movie_reservation
REDIS_URL=redis://localhost:6379/0
```

## Тестирование

Для установки зависимостей для тестов и запуска проверки используйте следующие команды:

```bash
uv sync --group test
uv run pytest
```

Тесты покрывают сценарии работы API и сервисов. Для изолированного запуска используется SQLite в памяти, поэтому проверка не зависит от локального PostgreSQL и Redis.
